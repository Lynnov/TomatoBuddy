# TomatoBuddy v1 发布阻塞与稳定性设计

## 1. 目标

本设计用于对照 `2026-05-18-release-prd.md` 推进 TomatoBuddy v1 的 P0 与 P1 发布准备工作。目标是让当前应用达到公开发布前的关键可用性和稳定性要求，同时避免扩展 v1 范围。

本轮覆盖：

- P0-1：Windows 打包流程失败的验证与替代发布策略记录。
- P0-2：迷你挂件不可拖动。
- P0-3：迷你挂件文字可读性。
- P1-1：跨天统计运行中不重置。
- P1-2：窗口 API 异常处理。
- P1-3：提示音资源释放。

本轮不覆盖：

- 账号、云同步、任务系统、历史图表、复杂养成。
- 新宠物、新主题、商店、自动更新。
- 大规模 UI 重设计或架构重写。

## 2. 设计原则

1. 发布阻塞优先：先解决用户无法使用、无法移动、看不清、运行出错的问题。
2. 稳定性闭环：每个 P0/P1 项目都要有代码、测试或手动验收路径。
3. 最小改动：沿用现有 React、domain、services、components 分层，只补齐缺口。
4. 系统边界安全失败：Tauri、Web Audio、打包工具这类外部边界失败时，不影响主计时流程。
5. 不扩大 v1 范围：不引入复杂设置项、统计系统或额外桌宠玩法。

## 3. 架构概览

当前结构保持不变：

- `src/App.tsx`：应用状态编排层，负责计时 tick、完成事件、统计更新、声音播放、持久化、窗口模式切换。
- `src/domain/*`：纯业务逻辑，包括计时、统计、恢复、时间格式化。
- `src/services/*`：浏览器和 Tauri 集成边界，包括本地存储、窗口控制、提示音。
- `src/components/*`：UI 组件，包括主界面、迷你挂件、像素猫、提醒卡片、设置面板。
- `src/styles.css`：像素风视觉样式和 mini/full 模式样式。
- `src-tauri/*`：Tauri 桌面壳配置和 Rust 入口。

本轮重点是让 `services` 层更安全，让 `MiniWidget` 具备可拖动交互，让 `App` 在完成专注时处理跨天统计。

## 4. 迷你挂件设计

### 4.1 拖动交互

迷你挂件需要一个明确的拖动区域。推荐在 `MiniWidget` 中加入拖动 handle，例如顶部或猫猫旁的小区域，用 `onMouseDown` 触发 `startWindowDrag()`。

交互规则：

- 鼠标按下拖动区域时尝试调用 Tauri 的 `startDragging()`。
- 拖动区域不承担恢复完整窗口的职责，避免拖动误触发展开。
- 双击迷你挂件仍恢复到 full 模式。
- 浏览器开发环境下拖动调用为 no-op，方便本地预览。
- Tauri 拖动失败时不阻止用户双击恢复完整界面。

### 4.2 文字可读性

迷你挂件保持透明背景，不引入大面积不透明卡片。时间文字使用像素风描边或多层 `text-shadow`：

- 主文字使用浅色或高亮色。
- 深色描边保证浅色桌面背景可读。
- 浅色外发光或细阴影保证黑色背景可读。
- 样式只作用于 mini 模式下的时间文字，不影响完整窗口倒计时视觉。

验收标准：

- 浅色背景下能清晰读出时间。
- 深色或黑色背景下能清晰读出时间。
- 透明挂件仍然轻量，不像普通卡片窗口。

## 5. 窗口控制设计

`src/services/windowControl.ts` 作为唯一 Tauri 窗口 API 边界。

### 5.1 `applyWindowMode`

职责：

- full 模式：恢复完整窗口尺寸，启用窗口装饰或符合当前 Tauri 配置的完整窗口状态。
- mini 模式：设置小尺寸、无标题栏、置顶状态。
- 始终通过安全封装执行。

失败策略：

- 非 Tauri 环境直接返回。
- 动态 import 失败直接返回。
- 任一窗口 API 调用失败都被捕获，不产生未处理 Promise。
- React 主界面不因为窗口控制失败而崩溃。

### 5.2 `startWindowDrag`

职责：

- 在 Tauri 环境中调用当前窗口的拖动 API。
- 在浏览器环境中 no-op。
- API 失败时静默返回。

## 6. 跨天统计设计

现有加载逻辑会在启动时按日期校正统计，但长时间运行跨过 0 点后，完成专注可能仍写入旧日期。本轮在完成专注瞬间补齐校正。

流程：

1. 计时 tick 检测到 `focus` 进入 `focusComplete`。
2. 获取当前日期字符串。
3. 对现有 `stats` 执行 `ensureTodayStats(stats, today)`。
4. 在校正后的统计上执行 `addCompletedFocus()`。
5. 保存更新后的 stats。
6. 播放完成提示音。

规则：

- 跨天只影响统计归属，不改变计时状态。
- 新一天完成的专注计入新日期的小鱼干和专注时长。
- 旧日期统计不进入历史列表，符合 v1 不做历史统计的范围。

## 7. 提示音设计

`src/services/sound.ts` 继续使用 Web Audio API 生成短促柔和提示音，但需要补齐资源释放和失败处理。

规则：

- `enabled === false` 时立即返回，不创建 `AudioContext`。
- 创建 `AudioContext`、节点、播放、停止任一步失败都捕获。
- 播放正常结束后关闭 `AudioContext`。
- 播放异常时也尝试关闭 `AudioContext`。
- 多次完成提示不应造成持续增长的音频上下文。

## 8. 打包验证设计

P0-1 的核心不是在代码里绕过 WiX 下载，而是让发布判定可复现、可解释。

验证命令：

```bash
npm test
npm run build
cargo test --manifest-path "src-tauri/Cargo.toml"
npm run tauri build
```

判定规则：

- 如果 `npm run tauri build` 成功，记录产物位置并进入手动启动验证。
- 如果失败原因是 WiX 下载超时或外部网络依赖，明确记录失败原因。
- 不能把 WiX 下载失败情况下的构建声明为完整成功。
- 如需发布，可在后续发布说明中明确采用便携 exe 或压缩包策略，但本设计不直接改发布文档。

## 9. 测试设计

### 9.1 单元测试

新增或调整测试覆盖：

- 跨天完成专注时，统计日期切换到当前日期。
- 提示音关闭时不会创建音频上下文。
- 提示音播放结束后会释放上下文。
- 窗口控制在非 Tauri 环境下安全返回。
- 窗口控制 API reject 时不会向外 reject。

### 9.2 组件与集成测试

新增或调整测试覆盖：

- `MiniWidget` 的拖动区域会调用 `startWindowDrag()`。
- `MiniWidget` 双击仍触发恢复 full 模式。
- `App` 在跨天完成专注时显示新一天的小鱼干。
- full/mini 切换失败不影响 UI 状态变化。

### 9.3 手动验收

手动验证：

1. 进入迷你模式。
2. 拖动迷你挂件，窗口位置变化。
3. 双击迷你挂件，恢复完整界面。
4. 在浅色背景观察时间，数字清晰可读。
5. 在黑色背景观察时间，数字清晰可读。
6. 浏览器开发环境切换 full/mini，无未处理异常。
7. Tauri 环境切换 full/mini，无未处理异常。
8. 连续触发提示音，无持续控制台异常。
9. 关闭提示音后完成专注，不创建声音播放流程。
10. 模拟跨天后完成专注，统计日期与当前日期一致。

## 10. 风险与取舍

- Tauri 拖动只能在桌面环境完整验证，浏览器测试只能验证调用路径。
- Windows 打包可能继续受 WiX 下载影响，本轮要求如实记录并明确发布判断，不伪造成功状态。
- 文字可读性优先于极致透明，如果透明与可读冲突，允许使用小范围描边或文字阴影。
- 本轮不保存挂件位置，位置持久化留到 v1.1 或后续优化。

## 11. 完成标准

本设计完成时应满足：

- 迷你挂件可拖动、可读、可返回 full。
- 窗口 API 失败不会造成未处理 Promise 或 React 崩溃。
- 跨天运行后完成专注不会把新一天奖励计入旧日期。
- 提示音开关有效，播放后释放资源。
- 自动化测试和前端构建通过。
- Rust/Tauri 测试通过。
- Tauri build 成功或失败原因被清楚记录。
