# TomatoBuddy 公开发布版 PRD

## 1. 产品概述

TomatoBuddy 是一个以像素猫陪伴为核心的轻量桌面番茄钟应用。它不是传统意义上偏工具化、偏数据分析的效率软件，而是一个“可爱的桌面陪伴物”：用户可以让一只像素猫常驻桌面，在工作、学习或日常使用电脑时，通过简单番茄钟、迷你挂件、提示音、小鱼干奖励获得轻量陪伴和专注节奏。

v1 的目标不是做完整效率系统，而是完成一个可以公开发布的最小可爱产品：稳定、可安装、好看、不打扰，并且具备明确的核心循环。

核心循环：

1. 用户打开 TomatoBuddy。
2. 看到像素猫和番茄钟。
3. 点击开始专注。
4. 专注结束后获得提示和小鱼干奖励。
5. 用户可以切换到透明迷你挂件，让猫猫常驻桌面。
6. 用户因为“可爱”和“陪伴感”愿意继续使用。

## 2. 目标用户

### 2.1 首发目标用户

v1 首发面向“泛可爱用户”。这类用户的核心动机不是寻找最专业的番茄钟工具，而是希望桌面上有一个轻量、可爱、有陪伴感的小东西。番茄钟功能是使用场景入口，像素猫和奖励反馈是留存动力。

典型用户包括：

- 喜欢桌宠、像素风、小动物陪伴感的用户；
- 学习、工作、写作、画画时希望有轻量节奏提醒的人；
- 不喜欢复杂效率软件，但愿意使用简单番茄钟的人；
- 希望桌面上有一个不打扰但能带来情绪价值的小挂件的人。

### 2.2 非首发核心用户

v1 暂不优先服务以下用户：

- 需要复杂任务管理、项目管理、统计报表的重度效率用户；
- 需要跨设备同步、账号系统、云端数据的人；
- 需要团队协作、共享番茄钟、排行榜的人；
- 需要高度可配置主题、插件、自动化工作流的人。

## 3. 产品定位

TomatoBuddy v1 的定位是：一个可公开发布的像素猫桌面陪伴番茄钟，重点提供可爱、轻量、稳定、低打扰的专注陪伴体验。

它应该给用户的第一印象是：

- “这个猫猫很可爱。”
- “我不用学就知道怎么开始。”
- “它可以变成小挂件放桌面上。”
- “专注完成后有一点奖励感。”
- “它不会烦我，也不会占用太多注意力。”

## 4. v1 产品目标

### 4.1 必须达成

v1 公开发布前必须满足：

1. 用户可以在 Windows 上安装或直接运行应用。
2. 应用启动后能展示完整像素猫番茄钟界面。
3. 用户可以完成一次完整专注流程。
4. 专注完成后有明确反馈，包括提示文案、提示音或小鱼干奖励。
5. 用户可以切换到透明迷你挂件模式。
6. 迷你挂件在桌面上可读、可移动、可恢复到完整界面。
7. 应用在常规使用中不出现明显崩溃、未处理错误或卡死。
8. 打包流程可复现，能产出公开发布所需的 Windows 包或可执行文件。
9. README 或发布说明中能说明如何安装、使用和反馈问题。

### 4.2 不追求达成

v1 不追求：

- 完整任务管理系统；
- 账号登录；
- 云同步；
- 多设备同步；
- 社交分享；
- 商店上架；
- 自动更新；
- 高级统计报表；
- 复杂皮肤商城；
- 多宠物系统；
- 移动端版本。

## 5. v1 功能范围

### 5.1 主界面

主界面需要包含：

- 应用标题；
- 像素猫；
- 当前计时状态；
- 剩余时间；
- 今日小鱼干数量；
- 今日专注时长；
- 开始 / 暂停 / 继续按钮；
- 重置按钮；
- 设置入口；
- 切换迷你挂件按钮；
- 专注完成或休息完成后的提醒卡片。

主界面体验要求：

- 用户首次打开不需要教程也能开始使用；
- 视觉风格保持像素猫、温暖、轻松；
- 主操作按钮清晰；
- 设置入口不抢占主流程；
- 完成一次专注后反馈明确。

### 5.2 番茄钟流程

v1 支持基础番茄钟流程：

- 开始专注；
- 暂停专注；
- 继续专注；
- 重置当前计时；
- 专注完成；
- 开始休息；
- 休息完成；
- 开始下一轮专注。

默认配置：

- 专注时长：25 分钟；
- 休息时长：5 分钟；
- 可在设置中调整。

番茄钟不需要支持：

- 长休息；
- 多轮循环配置；
- 任务绑定；
- 历史番茄记录列表；
- 复杂统计图表。

### 5.3 像素猫反馈

像素猫是产品核心资产，不只是装饰。

v1 中像素猫需要承担：

- 默认陪伴展示；
- 专注中状态反馈；
- 休息或完成状态反馈；
- 点击猫猫后的简短回应；
- 迷你挂件中的主要视觉主体。

猫猫反馈要求：

- 文案简短、温柔、可爱；
- 不频繁打扰用户；
- 不使用强压迫感文案；
- 不让用户感觉被监督。

### 5.4 小鱼干奖励

小鱼干是 v1 的轻量奖励系统。

规则：

- 每完成一次专注，今日小鱼干 +1；
- 今日小鱼干在主界面展示；
- 完成专注时展示奖励反馈；
- 小鱼干用于增强成就感，不进入复杂养成系统。

v1 不做：

- 小鱼干消费；
- 商店；
- 装扮购买；
- 经验值；
- 等级；
- 连续打卡系统。

### 5.5 设置

v1 设置应包含：

- 专注时长；
- 休息时长；
- 是否开启提示音；
- 是否默认启动为迷你模式；
- 是否窗口置顶。

设置要求：

- 修改后能保存；
- 重启应用后能恢复；
- 设置项数量保持克制；
- 不引入复杂偏好配置。

### 5.6 本地存储与恢复

v1 使用本地存储保存：

- 用户设置；
- 当前计时状态；
- 今日统计；
- UI 状态。

恢复要求：

- 应用重启后恢复用户设置；
- 如果用户开启恢复会话，应尽量恢复计时状态；
- 今日统计应按日期处理；
- 跨天后不应把新一天的专注错误计入旧日期。

### 5.7 透明迷你挂件

迷你挂件是 v1 的关键发布卖点之一。

迷你挂件需要满足：

- 可以从主界面切换进入；
- 背景透明；
- 无明显窗口标题栏；
- 无厚重边框和阴影；
- 显示像素猫；
- 显示剩余时间；
- 时间文字在深色和浅色桌面背景上都可读；
- 用户可以移动挂件位置；
- 用户可以通过明确操作回到完整界面；
- 挂件保持低打扰，不遮挡太多屏幕。

当前已知需要解决的问题：

1. 隐藏标题栏后挂件不可拖动；
2. 时间文字在黑色背景上可读性不足；
3. 需要确认窗口黑色投影是否完全消失；
4. 需要确认透明效果在 Tauri 实机中与测试一致。

### 5.8 提示音

v1 支持轻量提示音。

要求：

- 专注完成时播放；
- 休息完成时播放；
- 可在设置中关闭；
- 声音应短、柔和、不惊吓用户；
- 播放失败不应影响主流程；
- 不应导致控制台持续报错或资源泄漏。

## 6. 发布前必须解决的问题

### 6.1 P0：阻塞公开发布

#### P0-1：Windows 打包流程失败

当前 `npm run tauri build` 在 bundling 阶段失败，原因是 WiX 下载超时。

发布前要求：

- 能稳定产出 Windows 发布包，或明确采用可执行文件发布策略；
- 发布说明中写清楚安装或运行方式；
- 打包流程至少在本地可复现一次；
- 不依赖临时网络状态才能完成最终发布。

验收方式：

- 运行发布构建命令；
- 产出可分发文件；
- 在干净环境或至少非开发目录中启动验证。

#### P0-2：迷你挂件不可拖动

隐藏窗口标题栏后，用户必须仍能移动挂件。

发布前要求：

- 迷你模式下提供拖动区域或拖动交互；
- 拖动操作不应误触发展开；
- 拖动后挂件位置符合用户预期；
- 如果暂不保存位置，也要确保当前会话可移动。

验收方式：

- 进入迷你模式；
- 用鼠标拖动挂件；
- 挂件位置改变；
- 双击或指定操作仍可回到完整模式。

#### P0-3：迷你挂件文字可读性

透明迷你挂件需要适配不同桌面背景。

发布前要求：

- 时间文字在浅色背景可读；
- 时间文字在深色或黑色背景可读；
- 不破坏整体像素风格；
- 不引入大面积不透明背景。

可接受方案：

- 给时间加浅色文字；
- 加描边或 text-shadow；
- 使用小面积半透明文字底；
- 使用像素风描边。

验收方式：

- 在浅色背景观察；
- 在黑色背景观察；
- 时间数字清晰可读。

### 6.2 P1：强烈建议发布前解决

#### P1-1：跨天统计运行中不重置

当前统计在加载时会按日期校正，但应用持续运行跨过 0 点后，完成专注可能仍计入旧日期。

发布前建议：

- 完成专注前检查当前日期；
- 如果日期变化，先切换到新一天统计；
- 避免新一天的小鱼干计入旧日期。

验收方式：

- 模拟跨天；
- 完成专注；
- 确认统计日期与当前日期一致。

#### P1-2：窗口 API 异常处理

Tauri 窗口控制调用失败时，不应出现未处理 Promise 或影响主流程。

发布前建议：

- 对窗口模式切换做安全失败处理；
- 非 Tauri 环境下保持静默；
- Tauri API 调用失败时不让 React 主界面崩溃。

验收方式：

- 浏览器开发环境切换 mini/full；
- Tauri 环境切换 mini/full；
- 控制台无明显未处理异常。

#### P1-3：提示音资源释放

提示音播放失败或多次播放不应造成异常积累。

发布前建议：

- 播放完成后释放 AudioContext；
- 捕获播放失败；
- 保证关闭提示音时不会创建音频上下文。

验收方式：

- 连续触发多次完成提示；
- 控制台无持续异常；
- 提示音开关生效。

### 6.3 P2：可以发布后优化

#### P2-1：挂件位置持久化

v1 可以不保存挂件位置，但后续应考虑。

#### P2-2：更多猫猫状态

v1 只需要基础状态，后续可以加入更多动画或表情。

#### P2-3：更完整的奖励系统

v1 只保留小鱼干数量，后续再考虑养成或装扮。

## 7. 发布验收标准

### 7.1 自动化验证

发布前需要通过：

- 前端测试；
- TypeScript 构建；
- Vite 生产构建；
- Rust/Tauri 编译；
- Tauri 发布构建或替代发布流程验证。

建议命令：

```bash
npm test
npm run build
cargo test --manifest-path "src-tauri/Cargo.toml"
npm run tauri build
```

如果 `npm run tauri build` 因外部下载失败，必须：

- 记录失败原因；
- 明确替代发布产物；
- 明确后续修复方式；
- 不能模糊声称完整发布构建成功。

### 7.2 手动验收

发布前至少手动验证：

1. 首次启动应用；
2. 开始一次专注；
3. 暂停和继续；
4. 重置；
5. 完成专注；
6. 小鱼干增加；
7. 提示音开关；
8. 设置修改后重启恢复；
9. 切换迷你挂件；
10. 迷你挂件拖动；
11. 迷你挂件在深色背景可读；
12. 从迷你挂件回到完整界面；
13. 应用关闭重开；
14. Windows 可执行文件或安装包启动。

### 7.3 用户体验验收

v1 发布前主观体验应满足：

- 打开后一眼知道这是可爱的像素猫番茄钟；
- 主操作不需要解释；
- 猫猫不会遮挡主流程；
- 迷你挂件不会显得像一个坏掉的透明窗口；
- 深色桌面背景下仍能看清时间；
- 用户不会因为不能拖动挂件而卡住；
- 完成专注后有正反馈；
- 应用整体不显得粗糙或半成品。

## 11. 风险与取舍

### 11.1 最大风险：产品变成普通番茄钟

如果后续过度强调效率功能，TomatoBuddy 会失去差异化。v1 应优先保证“可爱、陪伴、桌面常驻”体验。

### 11.2 最大发布风险：打包不可复现

当前 Tauri 打包阶段存在外部依赖下载失败问题。公开发布前必须解决或制定替代发布策略。

### 11.3 最大体验风险：迷你挂件像半成品

透明挂件是关键卖点。如果不能拖动、看不清时间、有奇怪阴影，会直接影响第一印象。

### 11.4 范围控制

所有“听起来很有趣但不是公开发布必需”的功能，都应推迟到 v1.1 或之后。v1 的目标是发布一个完整、稳定、可爱的最小产品，而不是一次性做完整生态。

## 12. v1 发布判定

当以下条件都满足时，可以认为 TomatoBuddy v1 达到公开发布准备状态：

- 核心番茄钟流程可完整使用；
- 像素猫视觉和互动正常；
- 小鱼干奖励正常；
- 设置可保存和恢复；
- 透明迷你挂件可进入、可读、可拖动、可返回；
- Windows 发布产物可生成或替代发布方案明确；
- 自动化测试和构建通过；
- 关键手测场景通过；
- README / 发布说明完整；
- 已知问题不会阻塞普通用户首次使用。
