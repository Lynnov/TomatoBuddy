# SVG 小猫头像设计

## 目标

把当前用 CSS 拼出来的小猫替换成 SVG 小猫头像。第一阶段优先尽量还原 `参考图/寿喜Q.jpeg` 的坐姿三花折耳猫，而不是优先做多姿势或复杂分层动画。

## 范围

### 阶段一：参考图坐姿小猫

- 将参考图转换为高密度像素风 SVG 坐姿小猫。
- 保留 `PixelCat` 的可访问按钮语义，确保现有摸猫交互继续可用。
- 保留现有消息气泡行为。
- 通过 CSS 支持完整模式和 mini 模式下的不同尺寸。
- 只加入不破坏还原度的动画：轻微待机浮动/呼吸、点击微弹、现有消息气泡动画。

阶段一不包含眨眼、摇尾巴、走路、趴着休息姿势，也不包含用户上传图片功能。

### 阶段二：分层动画小猫

- 在可行范围内把坐姿 SVG 拆成有意义的图层：身体、头部、眼睛、尾巴、爪子、装饰元素。
- 添加不破坏参考图观感的动画：眨眼、尾巴轻摆、完成时爱心、不同状态的待机节奏。
- 为休息或暂停状态增加趴着休息姿势。

### 阶段三：走路姿势和上传生成管线

- 增加站立/走路姿势，作为一套独立 SVG 姿势，而不是从坐姿小猫变形得到。
- 调研并原型化未来的“用户上传猫图 → 像素 SVG 小猫”管线。
- 后续可评估的候选项目：
  - `image-tracer-ts` / `ImageTracer.js`：用于 JS/TS 侧 raster-to-SVG tracing。
  - `visioncortex/vtracer`：用于高质量 path 矢量化。
  - `giventofly/pixelit`：用于浏览器侧像素化和调色板控制。
  - `gametorch/image_to_pixel_art_wasm`：用于 WASM 量化。

## 架构

`PixelCat.tsx` 继续作为公开组件边界。调用方仍然传入 `mode`、`message` 和 `onPet`；组件内部从多个 span 拼图改为内联 SVG。

SVG 应以 React markup 的形式存在，而不是外部图片资源。这样 CSS 可以控制尺寸和动画，后续阶段也能对内部图层做精细动画。阶段一的 SVG 可以较密集并且基本静态，但明显的结构应尽量保留 class：`cat-svg`、`cat-body`、`cat-head`、`cat-eyes`、`cat-tail` 和 `cat-decorations`。

`styles.css` 负责尺寸、动画和不同窗口模式下的布局。小猫美术色值在可维护的前提下优先使用 CSS 变量；如果变量会影响阶段一还原度或让 SVG 难以维护，则允许在 SVG 中内联固定填充色。

## 数据流

- `App` 像现在一样把计时器模式和摸猫消息传给 `PixelCat`。
- 阶段一中，`PixelCat` 对所有计时器模式都渲染同一个坐姿 SVG。
- CSS 负责在完整模式和 mini 模式中缩放同一个 SVG。
- `onPet` 继续绑定在按钮点击事件上。
- mini 拖拽行为继续避开小猫图片本体；小猫保持为点击目标。

## 视觉方向

最终效果应接近参考图本身，而不是简化几何风格重画。关键视觉特征：

- 折耳和圆润坐姿轮廓。
- 灰色、焦糖色、奶油白三花色块。
- 大号金色眼睛，包含黑色瞳孔和白色高光。
- 深色粗像素描边。
- 白色胸口和肚皮区域。
- 卷曲尾巴和坐姿爪子。
- 如果组件尺寸允许，保留深色爱心和脚印类像素装饰。

SVG 的像素颗粒要比前期浏览器草图更细。避免过大的方块色块，否则在 mini 挂件尺寸下会显得粗糙。

## 测试

- 只有当组件结构变化影响查询或交互时，才更新 `PixelCat` / `MiniWidget` 相关测试。
- 可访问性测试继续围绕按钮角色和 `aria-label="摸摸猫猫"`。
- mini 交互测试继续验证点击小猫不会触发窗口拖拽。
- 运行定向组件测试、完整测试套件和生产构建。
- 因为这是前端视觉改动，需要在浏览器中验证完整模式和 mini 模式。

## 实现决策

阶段一应以参考图生成的高密度像素 SVG 作为起点，再按需要手动整理尺寸、透明背景和 markup。这比手写简化 SVG 更符合用户“尽量一模一样还原参考图”的目标。

用户上传图片生成小猫功能先延期。本次工作不应加入上传 UI 或新的图片处理依赖，除非这些依赖只用于开发阶段生成初始静态素材。
